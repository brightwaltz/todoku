# 公式ページから規則を作る

判定は規則のプログラムが行い、規則は公式ページから作る。Claude は規則を書く側で、窓口の画面では規則を書き換えない。この手順は、制度を足すときも、ほかの市へ広げるときも同じ。

## 1. 手続を引く（国の制度）

- 行政手続データの MCP サーバー（`.mcp.json` の `admin-procedures`、データセット `procedures-survey-r7`）で、その制度の申請の手続を探す。最初に `inspect_dataset` で列名を確かめ、`query_records` で手続名・法令名から探す。
- 見つけた手続は、手続ID・手続名・法令名・根拠条項号・申請時に添付させる書類をデータのまま控える。推測で条項を作らない。
- その制度だけの手続がない（税の控除など）ときは、実際に使う一般の手続を `match: general` で結び、データにその制度の記載がないことを `note` に書く。手続が何もないときは、規則を書く前に人に相談する。
- MCP が使えないセッションでは、非対話の Claude Code（`claude -p --mcp-config .mcp.json --strict-mcp-config`、書き込みの道具を渡さない）で探し、同じサーバーの CLI（`apcli query`）で手続ID ごとに引き直す。
- 控えた値は `tests/fixtures/procedures_r7.json` に足す（`tests/test_procedures.py` が規則ファイルと照らす）。

## 2. 公式ページを読む

- サブエージェント `rule-reader` に、制度ごとに公式ページを読ませる。制度が複数なら、数件ずつ振り分けて並行で読ませる。
- 報告の「読めなかったもの・分からなかったこと」を必ず見る。分からない条件は規則にせず、人に確かめる。

## 3. 規則ファイルを書く

- `rules/programs/<id>.yaml` に 1 制度 1 ファイル。形は既存のファイルと `docs/spec.md` の「規則ファイル」に合わせる。
- 条件は `rules/facts.yaml` にある事実だけで書く。新しい事実が要るときは facts.yaml に足し、問いの文・選択肢・確かめ方も書く（問いの文は利用者に出る）。
- 窓口の聞き取りで決まらない条件は `at_application`（申請で確かめる）へ。前提の手続きは `via`・`prereq` で書く。
- 出典は URL・発行元・利用条件・確認日。原文の引用（`quote`）は PDL1.0 のページだけ。**町田市のページの文章は写さない**（読み込みの検査が止める）。
- 書き換えると、PostToolUse のフック（`.claude/hooks/check_rules.py`）が読み込みの検査を回す。止まったら、その理由を直す。

## 4. テストと照合

- `tests/test_programs.py` に、その制度が「当てはまる見込み」「当てはまらない」になる場面を少なくとも 1 つずつ足す。どの制度にも出てくる道と出てこない道があることは `tests/test_rules_reachable.py` が確かめる。
- `uv run pytest` を通す。
- 原文を引用したら `uv run python scripts/check_quotes.py` で、引用が公式ページに一字も違わず載っているかを確かめる（ネットにつながる）。

## 5. 人が確かめる

- 規則ファイルの条件を、公式ページと人が見比べる。とくに金額・期限・対象者の線（年齢、所得、認定の区分）。
- README の「扱う制度」と「確認日」を更新する。

## ほかの市へ広げるとき

- 国の制度の規則はそのまま使える。申請先（`apply.where`）を、その市の担当課に置き換える。
- 市の独自制度は、その市の公式ページから 2〜4 の手順で 1 件ずつ作る。その市のサイトの利用規約を先に確かめ、転載が禁じられていれば原文を写さない。
