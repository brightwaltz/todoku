# 合成住民での試算（1 版目）

入口の出来事のボタンから始めた人に、相談の主題の外で、とどくが「当てはまる見込み」か「先に手続きをすると使える」と示す制度が 1 人あたりいくつあるかを数える。
架空の住民は facts.yaml の事実の値の組だけで作る。LLM も API も使わない。

```
uv run python eval/sim/run_sim.py                     # 2000 人、町田市・横浜市・青森県蓬田村（市区町村の型だけの例）
uv run python eval/sim/run_sim.py --rule extra        # 主題の事実を使わない主題の制度（下の一覧）も「直接つながる」に入れる
uv run python eval/sim/run_sim.py --rule none         # 主題に直接つながる制度も数える
uv run python eval/sim/run_sim.py --n 500 --seed 2 --city 132098 --json /tmp/sim.json
```

## 通し方

1. `population.py` が 65 歳以上の住民を作る（下の割合で、事実を 1 つずつ引く）。
2. その人に当てはまる入口の出来事を 1 つ選ぶ（`run_sim.py` の `THEME_FITS`。例：紙おむつを使っている人は「おむつが要るようになった」を押しうる）。どれにも当てはまらない人は数えない。
3. 画面で市区町村を選び、出来事のボタンを押したのと同じ事実を置く（`events.py` と `claude.check_extraction`）。
4. 問いに住民の値で最大 3 問答える（`eval/run_eval.py` の `simulate` と同じ）。
5. その市で結果の画面に出る制度（`visible`。`app.step_view` と同じになることを `tests/test_sim.py` で確かめる）のうち、「当てはまる見込み」と「先に手続きをすると使える」を数え、主題に直接つながる制度を除く。

## 主題に直接つながる制度（判断待ち）

既定の `--rule facts` は、出来事ごとに主題の事実（`THEME_FACTS`。例：おむつ → 紙おむつを使っている・失禁で布団を干せない）を決め、その事実を判定の条件に使う制度を「直接つながる」とみなす。前提の制度（prereq・via）の中の事実は見ない。
`--rule extra` は `facts` に、主題の事実を判定に使わないが主題に直接つながる制度（`run_sim.py` の `THEME_EXTRA`）を足す。足すのは次の 5 件だけ。

| 出来事 | 足す制度 | 足す理由 |
|---|---|---|
| 転びやすくなった（falls） | 介護保険の住宅改修費の支給（jutaku-kaishu）・福祉用具購入費の支給（fukushi-yogu-konyu）・町田市の住宅設備改修給付（machida-jutaku-setsubi） | 規則によっては認定の区分と暮らしている所だけで判定され、`facts` では転倒に直接つながる制度が 0 件になる |
| おむつが要るようになった（diapers） | 町田市の在宅高齢者紙おむつ支給（machida-kami-omutsu）・横浜市の高齢者紙おむつ給付（yokohama-kami-omutsu） | 紙おむつを使っているかを聞かずに、認定の区分・住民税などで判定される |

ほかの出来事（discharged・forgetful・alone・work）には足していない。`--rule none` は除かない。出来事ごとの制度の一覧を全部手で作る決め方は入れていない。

stat は統計の公式の頁（表・CSV）の数から置いたもの（2026-11-05 に照らした）。頁の文は写さず、数だけを使った。assumed は統計が見つかっていない仮定。照らし直したら `population.py` の定数だけを差し替える。`tests/test_sim.py` の `test_population_matches_the_checked_statistics` が、作った住民の割合が上の stat の数から大きく外れないことを確かめる。
事実は互いに独立に引く（上の表で書いた依存だけを入れた）。問いには、住民はいつも正しく答える（「わからない」と答える人はいない）。

## 結果の読み方

数は規則の版で変わる（dev と dev-merge では facts.yaml と規則が違う）ので、ここには書かない。流した版のコミットと一緒に残す。

- 主題の外が「先に手続きをすると使える」に偏るときは、`--json` の `top_outside_programs` で、要介護・要支援認定の申請が先になる制度（高額介護サービス費・障害者控除など）かを見る。規則が「認定の申請」を「当てはまる見込み」と出すのは「申請できる」の意味で、認定されるかは言っていない。
- `--rule facts` は、主題の事実を判定に使わない制度を「直接つながる」と数えられない。たとえば dev-merge の規則では住宅改修・福祉用具の購入が認定の区分と暮らしている所だけで判定されるので、「転びやすくなった」の主題に直接つながる制度が 0 件になる。`--rule extra` はこの穴を上の一覧で埋める。
- 住民税・世帯の一部・認知症・暮らしている所などは assumed なので、数はその仮定に左右される。外に言うときはそう書く。
