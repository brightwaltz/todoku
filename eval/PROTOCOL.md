# 正解の作り方（2026-11-03、流す前に決めた手順）

架空事例 30 件×32 制度の正解を、人が全部付けるのではなく、**独立した 2 つの読みを突き合わせ、食い違いだけを人が裁く**形で作る。
人が全部付ける案（960 マス）は、一人では付けきれないと柴田が判断した（2026-11-03）。この文書は、読み B を流す前にコミットする。
流したあとに変えたことは、末尾の「変更の記録」に理由と一緒に書き足す。

## 2 つの読み

| | 読み A（規則） | 読み B（目隠しの Claude） |
|---|---|---|
| 入力 | 事例の「聞かれたときの答え」（`eval/cases/cases.yaml` の answers）をすべて | 制度の名前、公式資料の本文、事例の相談文と人物の説明 |
| 判定 | `engine.evaluate` | Claude（道具なしの Messages API 呼び出し、構造化出力） |
| 入れないもの | — | 規則ファイル、判定結果、規則を書いた人の要約（summary）・条件の label・資料の title |

- 読み B には道具を渡さない。規則を読む手段がないので、「規則を見ないで」と指示して守らせる形ではない。
- 公式資料は、規則の `sources` の URL から `eval/sources.py` で取った本文（`eval/out/sources/`、.gitignore 済み）。
  e-Gov の法令は、規則の title に書いた条だけを e-Gov 法令 API で切り出す。町田市のページは転載不可なので、
  本文も引用もリポジトリに入れない。引用は非公開の裁定ページにだけ出す。
- 付け方の定義は、柴田の正解付けページの「はじめに」と同じ文（`eval/blind_read.py` の READ_SYSTEM）。
- 判定ごとに、決め手（自分の言葉で 1 文）と、公式資料からの引用（一字一句そのまま）を付けさせる。

### モデルと設定

- 読み B はモデルを変えて 2 回：`claude-fable-5-1` と `claude-sonnet-5-5`。規則を書いた Opus 5.5 は使わない（同じモデルだと思い違いがそろいやすいため）。
- effort は high。制度ごとに 1 回呼ぶ（その制度の資料と、範囲の事例全員）。事例の一覧はキャッシュする。
- 指示文の SHA-256：READ_SYSTEM `e10a7c5e607c9940d686f34f04a8d8fa9fb6f2abb6eddab64f5c3e3c8ac59cc7`、
  FACTS_SYSTEM `c04a135f457889225a08150d492f34a37300456130ab809003222cbf211b8d0c`。

### 事例に足りなかった事実

規則が使う事実のうち 3 つ（`severe_constant_care`・`money_management_difficulty`・`hearing_certifiable`、制度 22・23・25）は、
どの事例にも答えがなかった。これを、道具なしの呼び出し（`claude-opus-5-5`、FACTS_SYSTEM）で、相談文と人物の説明だけから
「はい／いいえ／わからない」で書き足す。規則も判定も渡さない。返ってきた答えは手を加えずに answers に入れる。

## 突き合わせ（`eval/adjudicate.py`）

マスの印：○＝当たりうる、×＝当たらない（済んでいるを含む）、？＝決められない、申＝申請済み・結果待ち。

- 読み A：eligible・after_prereq→○、ineligible・done→×、unknown→？、pending→申
- 読み B：当たりうる→○、当たらない・済んでいる→×、決められない→？、申請済み・結果待ち→申

**一致**：A と B の 2 回が同じ印で、申を含まず、B の ○・× の引用がどれも原文に見つかる（NFKC、空白と表の区切りを除いて部分一致、8 字以上）。
一致したマスは、その印を正解にする（？は採点に入れない）。

**論点**：一致しなかったマスを、次の鍵でまとめる。

- 申を含む → 「制度×申請済み・結果待ち」
- 印は全部同じだが引用が原文にない → 「制度×引用が原文に見つからない」
- 印が割れた → 「制度×A の印×A の決め手（満たさない条件・分からない事実・先に要る手続き）」

**抜き取り**：一致した ○ と × から、乱数の種 20261103 で ○ 20 マス・× 20 マス（足りなければ全部）。
両方の読みが同じ間違いをしている率の上限を見積もるため。

## 柴田が裁く

- 論点ごとに、A と B の言い分を、どちらが規則かを伏せて順不同に並べる。公式資料の引用とリンクを添える。
- 論点ごとに ○・×・？ を 1 つ選ぶと、その論点のマス全部に効く。マスごとに変えることもできる。
- 抜き取りは、マスごとに ○・×・？ を選ぶ（A・B の印は見せない）。
- 裁いた印を正解にする。抜き取りで一致と違う印になったマスは、柴田の印を正解にし、「誤り」として数える。

## 報告すること

- 読み B の全部の回（試しを含む）の費用と、欠けた答え・引用の照合の結果。
- マスの数、一致の数（印ごと）、論点の数とマスの数、A と B の一致率、B どうしの一致率。
- 抜き取り「N 件中 k 件が誤り」と、その上限。
- 裁いた結果、規則を直したもの・事例を直したもの・規則が正しかったものの数。
- そのうえで、3 つの比べ方（規則だけ・窓口全体・Claude だけ）の数字。

## 限界（そのまま書く）

- 読み B も Claude なので、正解は Claude の読み方に寄りうる。「Claude だけ」の比べ方には有利な向きの偏りで、とどくの数字は控えめに出る。
- 公式資料の選び方（どの URL を読むか、e-Gov のどの条か）は規則を書いた側が決めた。資料が足りなければ、B は「決められない」と答えられる。
- 制度 2 の厚生労働省の PDF（001725284.pdf）は画像だけで文字が取れない。B には「文字を取り出せなかった」と渡す。
- 正解の最後の決め手は柴田 1 人の判断。
- 食い違った 165 マスと別に見た 2 マスの正解は、規則を書いたのと同じモデル（Opus 5.5）の推しを、柴田がすべてそのまま承認したもの（推しから変えたマス 0。うち 61 マスはチャットの一言で一括して承認）。正解は推しと規則の思い違いに寄りうる。抜き取りは行わなかったので、一致したマスの誤り率の上限は出せない。

## 費用
